First public release.

OpenPush for Android is a receive-only SDK: it registers a device with OpenPush, reports what
happens to each notification, and never sends messages itself.

- Device registration with a provider token supplied by the app or fetched by the optional
  Firebase Cloud Messaging module, with users, tags, aliases and subscription state kept in sync.
- Durable delivery and click receipts, custom events and session tracking that survive
  offline periods and process restarts.
- An optional Firebase module that renders notifications (images, action buttons, grouping,
  replacing a shown notification, launch URLs) and handles taps, plus background data-only pushes.
- Optional in-app messages and Android Live Updates.
- Email addresses, SMS and WhatsApp numbers, and phone verification codes on the user.
- A notification permission prompt that needs no Activity result forwarding.
- The `ai.openpush.setup` Gradle plugin, which finds the push setup an app already has and wires
  OpenPush in around it.
- An optional compatibility layer for apps moving from another push SDK, with a migration
  guide and a migrated example app.

## Upgrading from 1.1.x/1.2.x

Upgrading needs no code change: every public member keeps its signature, and the device
credential, subscription and queued receipts and events carry over.

- `Notifications.requestPermission` keeps the shapes 1.2.1 had. In a coroutine,
  `val granted = OpenPush.Notifications.requestPermission()` (or
  `requestPermission(fallbackToSettings = true)`) suspends until the user answers. Outside a
  coroutine, such as in `onCreate`, pass a callback:
  `requestPermission { granted -> … }` or `requestPermission(activity) { granted -> … }`. Java
  calls the callback form, `requestPermission(false, granted -> Unit.INSTANCE)`. The prompt
  runs in OpenPush's own Activity, so nothing needs forwarding; existing forwarding into
  `onPermissionResult` is harmless.
- Callbacks run on the main thread: subscription and permission observers, the
  `requestPermission`, `login`, `logout`, email, `Verify` and `receipt` callbacks,
  `onRegistered`, `onRegistrationFailed`, the identity callbacks and the in-app listeners. They
  are posted, never run inside the call that caused them, and arrive in order. Foreground and
  background-message listeners stay on the thread that delivered the push, and `onLog` on the
  thread that wrote the line. Do not block the main thread waiting for a callback.
- `register(token, externalId)` is deprecated (a compiler warning, same signature): a new
  external id is now logged in first, as `login(externalId)` without an auth hash, so an
  identity is only ever attached through login. Use `login` and `register(token)`.
- In Kotlin, a third positional string in `initialize(context, appId, "…")` is the SDK key, as
  it always was in Java. A value starting with `http://` or `https://` is still read as the
  server URL with the key from manifest meta-data, and logged; name it,
  `serverURL = "…"`, to silence the log.
- `@OpenPushInternalApi` is an error-level opt-in. It marks seams that were never public API.
- Receipts the server refuses with a 4xx other than 429 are dropped instead of blocking the
  queue, and a receipt is given up after 7 days or 10 server failures. Receipts already queued
  on a device drain as before.

## Fixed

- In-app messages: the dim behind a center, full-screen or carousel message now covers the
  camera cutout and the status and navigation bars, while the message itself stays clear of
  them. Banners are unchanged.
